用 `skill` 工具加载 `project-reading-method` 与 `project-doc-map`，然后执行「/read」（`$ARGUMENTS` 可指定子系统/路径）。

1. **分档**：按「判断项目大小」判据归档（模块数/业务复杂度为核心、行数兜底），判据与理由写进 `MAP.md` 与 `others/项目解析.md`。
2. **阅读**：按档位策略执行——微型/小型 = 全量精读；中型 = 主干 100% + 外围抽样 ≥30%；大型 = 分层抽样 + 圈定目标子系统；巨型 = **先与用户确认目标子系统**再深读。默认在同一会话分批阅读；独立模块可委托 `@module-reader`（只读、带证据笔记）。
3. **产出**（全部在 `learning_plan/<项目>/` 内）：
   - `MAP.md`：总目标 + 全局驱动问题 + `## Labs` 候选索引（骨架；画像缺失时只出骨架并标「待 /profile」）；
   - `PROFILE.md` §3 前置自检：依画像裁剪出"本项目 Lab 真会用到的概念"，每条给检验入口/小测 + 缺失去处；
   - `others/项目解析.md`：事实层四节——结构/入口/主链路/依赖/扩展点、**验证命令清单**、**可实验点清单**、概念速查。
4. **汇报**：档位与判据、覆盖/未覆盖清单、未确认项；每条结论带证据（`文件::符号`）。

规则：

- 画像缺失（未执行 `/profile`）时**只产出骨架**，不臆造 Lab 与驱动问题；
- 大型/巨型项目先与用户确认范围，未读部分写进 `others/项目解析.md`「风险与未覆盖」；
- 不确定的写「未确认」，不猜 API 含义，不编造路径与网址；
- **不要创建 `KNOWLEDGE.md` 或 `stages/`**（已退役）。
