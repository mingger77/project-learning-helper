# project-doc-map（MAP.md 撰写规范）

定位：**项目学习指引**——问题驱动地图，**只做"指路"**。细节（学习路径、Out of Scope、评分构成、提示）全在 `labs/NN-<slug>/LAB.md`，MAP 不重复。

由 `/read`（结构与骨架）与 `/lab`（分数与状态）共同维护；画像在 `PROFILE.md`，MAP 不放画像。

## 结构模板

```markdown

> 本文档为项目 <项目名> 的学习导航：先看「总目标」与「驱动问题」，再按 Lab 推进。
> 学习者画像见 [PROFILE.md](PROFILE.md)；每个 Lab 的完整 handout 见 `labs/NN-<slug>/LAB.md`。
```

## 生成规则

- 画像缺失（未执行 `/profile`）时：只写「总目标（待确认）+ 结构骨架 + 候选 Lab 标题」，标注「**待 /profile**」；**不得臆造 Lab 与驱动问题**。
- Lab 划分依据：`/read` 的「可实验点清单」× `PROFILE.md` 的目标与粒度偏好；一个 Lab = 一个能力 = 一个可评分实验。
- 顺序 = 依赖顺序（先跑通 → 再改得动 → 再看懂内部）；粒度按 `project-lab-method` 第一节。
- Lab 数量：微型/小型 2-4；中型 4-8；大型/巨型按圈定子系统拆分（先确认范围）。

## 稳定锚点（状态栏与工具依赖，勿改格式）

- 全局问题表行首列必须是 `| Q1 |`（`Qn` 全局唯一，被 `LOG.md` 的「关联」与 `LAB.md` 的驱动问题引用）；
- 区块标题固定为 `## Labs`；
- Lab 标题固定为 `### Lab <N>：<标题>`（解析器同时兼容旧写法 `### 阶段目标<N>：`）；
- 状态单独一行：`- **状态**：未开始|进行中|已通过`（三值）；
- 评分单独一行：`- **评分**：<score>/<max>（阈值 <threshold>）`（未评分写 `0/100（阈值 100）`）。

格式被破坏时状态栏与 `learning_status` 会退化为「未知」，但不会报错；发现退化请顺手修正。

## 规则

- **Lab 区块只写四行**（驱动问题 / 状态 / 评分 / `LAB.md` 链接）：学习路径、Out of Scope、评分构成、交付物、提示一律不放 MAP。
- **Lab 推进判定**：`评分 ≥ 阈值` ∧ `驱动问题已答（或显式推迟并说明理由）` ∧ `REPORT.md 已填`——由分数与状态决定，不看轮数或篇幅。
- 状态与分数三处一致：`MAP.md` ↔ `LOG.md`（grade/completion 条目）↔ `labs/*/autograder/last-result.json`（以及 `REPORT.md` 的 grading 区块）。
- `MAP.md` 不写结构全览 / 数据流 / 状态机 / 证据索引——那些在 `others/项目解析.md`。
- `KNOWLEDGE.md` 与 `stages/` 已退役，不要创建。
