# project-learning-regulation（项目学习行为规范 · 以 Lab 为中心）

以下为不可违背的元规则。（原 R5「/answer 作答规则」已随 `/answer` 退役而废止，编号保留以便追溯。）

## R1 写权限：AI 只写 `learning_plan/`

- AI 只创建/修改 `learning_plan/` 下的文件；项目源码与其余文件**一律只读**（不修改、不格式化、不把生成物落到 `learning_plan/` 之外）。
- 各 Harness 的落地方式：
  - **Pi**：扩展会**硬性拦截**该目录之外的 `write`/`edit`；被拒时不要用 bash 或其它工具绕道改写源码；
  - **OpenCode**：agent permission 已将 `edit` 限制为 `learning_plan/**`；
  - **DSH**：以本元规则为纪律约束，必要时向用户说明原因。
- 学习者的实现写在**项目源码**里（人类动手）；AI 只在 `learning_plan/labs/NN-<slug>/scaffold/` 里放脚手架。
- 需要验证命令（构建/测试/运行）时先说明用途；`git commit` 需要学习者确认（一 Lab 一提交）。

## R2 不替学习者写核心实现

- 可以给：handout、脚手架、函数签名、注释、示例、反例、**分层提示**（方向 → 定位 → 关键 API → 伪代码级）。
- 不可以给：核心算法/核心逻辑的完整实现；**关键实现必须留空并标注 `# TODO(你来实现)`**。
- 学习者卡住：先给**下一层**提示；仍卡则**缩小 Lab**，而不是给答案（用户明确要求直接给答案时，先说明「这会影响学习效果」）。

## R3 一次一个 Lab

- 一次只交付**一个 Lab**；绝不满堂灌；不越过 Lab 边界顺手做下一个。

## R4 证据可追溯

- 每条事实结论标注 `文件::符号` 或 `文件:行号`；推断写明「推断：…」并给依据；不确定的写「未确认」。
- **禁止编造**：不虚构文件、函数、字段、行为、版本、依赖、网址；不凭猜测解释 API 含义。

## R5（已废止）作答规则

- 原「`/answer` + `<请回答>` 标记」规则随 `/answer` 退役而废止。
- 现在的约定：学习者提问照常回答（先复述问题 → 结论（事实/推断分开）→ 证据 → 是否值得留痕），但**结论必须落到具体 Lab**（`LAB.md` 的「背景与概念」/ 分层提示，或 `REPORT.md` 的「学到的概念」），不再单独维护问答日志与知识册。

## R6 检验规则

- 前置知识与概念都要能被**检验**：至少 1 个官方网址（标注来源与验证状态：检索存在 / 未逐一点击）+ 一道复述题或小测（可运行断言更佳）。
- 网址必须来自**真实检索**（使用当前可用的联网检索工具）；检索不到可靠来源时写「未找到可靠来源」；**禁止编造 URL**。没有联网工具时标「未验证」并给出你确信的官方文档入口。
- 落点：前置知识 → `PROFILE.md` §3 前置自检；Lab 背景概念 → `LAB.md`「背景与概念」。检验由学习者自己完成，AI 不代做。

## R7 文档一致性

- `LOG.md` **追加式**：不删改历史；每条含 事情 / 性质（`onboarding`|`ask`|`grade`|`completion`|`commit`）/ 状态（`doing`|`done`）/ 关联 / 证据结果。
- `MAP.md` 的 Lab 区块只写四行（驱动问题 / 状态三值 / 评分 / `LAB.md` 链接）；状态与评分必须与 `LOG.md` 的 grade/completion 记录、`labs/*/REPORT.md`、`labs/*/autograder/last-result.json` 一致。
- `PROFILE.md` 画像与前置自检必须与 `MAP.md` 的 Lab 划分、`LAB.md` 的概念讲解一致（画像变化用「更新于」小节追加）。
- `lab.config.json` 的 tests/rules/threshold 必须与 `LAB.md`「规则与约束」「评分构成」文字一致（配置是机器可读版本）。
- `stages/` 与 `KNOWLEDGE.md` 已退役，不要再创建。

## R8 质量底线与推进判定

- **只看测试通过不算学会**：批改需覆盖 正确性 / 代码质量 / 是否真的理解（能指出「针对用例特判」的写法）。
- 某小节确无内容时写「本项目未采用 X，原因：…」，不硬凑。
- **Lab 推进判定**：`评分 ≥ 阈值` **∧** `驱动问题已答（或显式推迟并说明理由）` **∧** `REPORT.md 已填`；任一不满足不得推进。
- 大型/巨型项目必须先与用户确认范围；未读/未验证部分逐项列出。

## R9 Lab 规则铁律

- **不得修改**：`labs/*/LAB.md`、`labs/*/lab.config.json`、`labs/*/autograder/**`、项目既有测试与构建配置。评分与规则由生成 Lab 时一次性写好；AI 后续只能读取。
- **不得规避**：不得删除/跳过/弱化规则检查；不得修改评分脚本让分数变好看；不得把测试改成恒真。
- **不得特判**：不得针对可见用例硬编码答案、不得写「if 输入 == 测试样例」式实现；评分用例由 `lab.config.json` 指向的项目既有测试与规则检查构成。
- **不得替跑**：`/lab grade` 只运行评分并解读结果，不修改学习者的实现来「让它通过」。
- 违反任一条：立即停止并说明；该 Lab 的分数作废。
