# project-doc-knowledge（KNOWLEDGE.md 撰写规范）

定位：**前置知识详解**，面向学生。依据「学习者画像卡」（编程水平/已有相关经验）生成；STUDENT.md §3 只保留一个指向本文件的跳转链接，详细讲解全部放在本文件。每个知识点都要讲透并附**检验网址**（供学生自测/查证）。

## 生成规则

- 依据画像决定「已具备/可能缺失」两栏：已具备的只进 §1 自检表，不重复详解；缺失的按 §2/§3 详解。
- 数量随画像与档位裁剪：微型项目 3~8 条；小型 5~10 条；中型 10~20 条；大型/巨型按圈定子系统的前置需求（不设上限，按需要）。
- **禁止一句带过**：每个知识点至少包含 是什么（2-3 句）+ 为什么需要（关联本项目，标注 `文件::符号`）+ 怎么理解（例子或类比）+ 常见误区。
- **检验网址规则（对应 project-learning-regulation R9，硬性）**：
  - 每个知识点至少 1 个官方文档网址；建议再配 1 个在线练习/测验网址；
  - 网址必须来自联网检索（web_search）的真实结果，标注来源（官方/社区）与验证状态（检索存在/未逐一点击）；
  - 检索不到可靠来源时写「未找到可靠来源」并留空说明，**绝不编造 URL**；
  - 网址是给学生点击检验用的，AI 不替代学生完成检验。

## 结构模板（6 节）

```markdown
# KNOWLEDGE.md —— <项目名> 前置知识详解

> 面向学生：学本课前需具备的概念/工具/术语详解与检验网址；依据你的画像生成。
> 先做 §1 自检，缺失项按 §2/§3 学习，用检验网址验证；疑问写入 QUESTION.md。

## 0. 使用说明
   自检流程：对照 §1 表格逐项勾选 → 缺失项进入 §2/§3 对应条目学习 → 点击检验网址自测/查证 → 完成后回到 STUDENT.md §5 学习路线
   检验网址约定：每条标注来源（官方/社区）与验证状态（检索存在/未逐一点击）；AI 不代你完成检验

## 1. 知识自检表
   | 知识点 | 你已具备？ | 检验网址 | 学完自测 |
   |---|---|---|---|
   | （示例）变量与作用域 | 是 / 否 | [MDN](https://...) | 能解释 const 与 let 的区别 |

## 2. 概念详解（核心）
   每个知识点一节：
   ### <知识点名称>
   - 是什么：2-3 句讲清概念
   - 为什么需要：本项目哪里用到（文件::符号），不懂它会卡在哪
   - 怎么理解：一个例子或类比
   - 与其它知识点的关系：（可选）
   - 检验网址：[官方文档](URL)（来源：官方，检索存在）；[在线练习](URL)（来源：社区，未逐一点击）
   - 常见误区：一个最常犯的错

## 3. 工具与环境
   学习本项目所需工具（git/构建工具/调试器/包管理器等），结构同 §2

## 4. 术语速查
   术语 → 一句话 + 指向 §2 条目或外部链接（与 STUDENT.md §9 互补，不重复展开）

## 5. 延伸阅读（可选）
   官方文档/教程合集列表（每条标注未验证）
```

## 约定

- 本文件随 STUDENT.md 一起更新：画像变化 → 重写 §1 自检表与缺失项详解；QUESTION.md 出现共性前置疑问 → 补进对应知识点或 §5。
- 与 STUDENT.md 的链接是双向的：STUDENT.md §3 → 本文件；本文件 §0 → STUDENT.md §5。
- 相对路径/相对链接，保证 `learning_plan/<项目名>/` 目录内可移植。
