# project-doc-student（STUDENT.md 撰写规范）

定位：**给学生看的学案**。老师（即 AI）依据 TEACHER.md 编写；学生按学案边读边做，作答区直接填写在文件内；疑问统一写入 QUESTION.md。

## 生成前置

- 依据「学习者画像卡」（编程水平/学习目标/想学知识/已有经验/文档偏好）生成；§3 前置知识必须与画像一致。
- 文档中的章节号与 TEACHER.md 的引用必须真实存在（见 project-learning-regulation R8）。

## 结构模板（11 节）

```markdown
# STUDENT.md —— <项目名> 学习学案

> 面向学生：老师（即AI）依据 TEACHER.md 编写；学生按本学案学习，边读边做，
> 作答区可直接填写在本文件中；疑问统一写入 QUESTION.md。

## 0. 本课信息
   项目名/版本/学习者画像（转录自询问阶段）/建议学习时长/学完你将获得什么（承诺清单，不夸大）

## 1. 目录（章节跳转）
   本文件锚点 + TEACHER.md 跨文件链接，例如：
   - 本文件：[§2 项目速览](#2-项目速览) ｜ [§3 前置知识](#3-前置知识) ｜ … ｜ [§11 补充内容](#11-补充内容)
   - 跨文件：[TEACHER.md §5 关键机制](TEACHER.md#5-关键机制)
   锚点约定：默认用标题生成的 `#<标题>`；查看器不支持中文锚点时，在目标标题旁加
   HTML 锚 `<a id="sec-N"></a>` 并用 `#sec-N` 跳转

## 2. 项目速览
   一句话定位（它解决什么问题）+ 一句话整体叙事（输入→处理→输出）；先看整体，再进细节

## 3. 前置知识（依据学习者画像生成）
   依据「询问用户」阶段的编程水平与已有相关经验生成——学本课前需具备的
   概念/工具/术语清单（每项一句话 + 指向本学案相应章节或外部资料）；
   明确"你已具备 / 可能缺失"两栏；缺失项给出补课提示（术语见 §9 术语表，可联网检索）
   【约定】不重复讲授已具备的知识；缺失项是后续学习路线的前置条件

## 4. 环境与运行
   依赖/安装/运行/测试命令（每条标注已验证/未验证）+ 最小可运行示例 + 常见调试方式
   【作答区】记录你实际运行的结果与报错

## 5. 学习路线（核心）
   分阶段：每阶段 = 读哪些文件（路径清单）→ 做什么（任务）→ 检查点（自测题）
   阶段顺序对应 TEACHER.md §6 的阅读路径设计；每阶段末尾标注"你将学会什么"
   【跳转】每阶段/关键概念处提供 `[详见 TEACHER.md §x](TEACHER.md#x-标题)` 跨文件链接

## 6. 核心知识
   概念要点：定义（一句话）→ 代码位置（文件::符号）→ 为什么这样设计 → 常见误解
   （学生版简洁版；深入链接：`[TEACHER.md §2~§5](TEACHER.md#2-结构全览)`）

## 7. 动手练习
   练习集（由易到难）：每题 = 题干 → 提示 → 验证方式 → 完成后自检
   【作答区】每题下方留空：做法 / 输出 / 遇到的问题
   （题号与 TEACHER.md §7 练习设计一一对应）

## 8. 常见坑
   症状 → 原因 → 避免（学生视角，不必懂原理也能绕开）

## 9. 术语表
   词汇 → 代码对应（指向具体文件::符号）

## 10. 检查点清单
   全部检查点汇总（学完自测）；对不上答案的条目，把疑问写入 QUESTION.md

## 11. 补充内容（依据 QUESTION.md 生成）
   来自 QUESTION.md 中已回答问答的共性/精华部分（高频问题、误区澄清、追问补充），
   在更新学案时同步追加；每条注明"源自 QUESTION.md 第 N 条"；
   无内容时写明"暂无补充内容；有疑问请写入 QUESTION.md"
```

## 约定

- 学生视角写作：少用术语堆砌，任务式引导（"读完 src/core/，回答：…"）。
- 每条练习/检查点都要有验证方式（命令、输出断言或自测问题）。
- 跨文件链接用相对路径（`TEACHER.md#...`），保证 `learning_plan/<项目名>/` 目录内可移植。
- 更新节奏：学生学完一课或 QUESTION.md 出现已答共性问答时，同步刷新 §11 补充内容。
