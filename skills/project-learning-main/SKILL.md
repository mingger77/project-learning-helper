# project-learning-main（项目学习模式顶层调度）

本 skill 为 DeepSeek Harness 项目学习模式的 Agent 提供「人利用 AI 辅助进行项目式学习」的完整流程：**阅读项目 → 产出 `learning_plan/<项目名>/` 三份文档**。

## 使用场景

适用于「学习 / 阅读 / 讲解 / 梳理某个代码库」类请求。不适用于：修改项目代码、功能开发（应回到编码模式）。

## 输出文件（仅有三份，无 SUMMARY.md、无 README 索引）

- `learning_plan/<项目名>/TEACHER.md` —— 老师（即 AI）备课解析（先写；事实仓库 + 教学设计）
- `learning_plan/<项目名>/STUDENT.md` —— 学生学案（后写；11 节结构）
- `learning_plan/<项目名>/QUESTION.md` —— 问答日志（初始化：模板 + 使用说明 + 示例行）

**固定约束**：除 `learning_plan/` 外，项目其余文件一律只读；联网始终允许；不再询问时间预算 / 验证权限 / 联网许可。

## 执行流程

1. 立即加载（`skill` 工具）：
   - `project-learning-regulation`（元规则，先读）
   - `project-reading-method`（复杂度分档判据 + 五轮阅读法）
2. 确认目标项目与学习者背景：
   - 用户已给路径：以该路径为项目根；未给且 cwd 是项目根：用 cwd；均不满足：用 `ask_user_question` 确认。
   - 询问 5 项：编程水平 / 学习目标 / 想学的知识 / 已有相关经验 / 文档偏好（语言、篇幅、讲解风格）。
   - 大类项目（大型/巨型）先协商范围（目标子系统、单包/核心路径）。
3. **复杂度分档**：按 `project-reading-method` 的「判断项目大小」判据归档（模块数/业务复杂度为核心、行数兜底），把判据与理由写入 `TEACHER.md` §0/§1。
4. **画像与计划汇总 + 双确认**：展示「学习者画像卡」（水平/目标/已有经验/风格偏好）+「项目卡片」（名称/档位/判据/入口/构建命令），请用户确认（a）档位与阅读策略（b）输出默认值（目录/三份文件名/语言）；确认后才开始阅读，阅读中不反复打断（除非档位与目标严重不匹配）。
5. **按档位策略阅读**：执行 `project-reading-method` 五轮法；档位决定策略（微型=全量精读一次完成；小型=全量精读一轮；中型=主干 100%+外围抽样 30%；大型=分层抽样+子代理委托；巨型=导航式阅读，先确认目标子系统）。
6. **依次产出文档**：
   - 先写 `TEACHER.md`（9 节，按 `project-doc-teacher`）；
   - 再写 `STUDENT.md`（11 节，按 `project-doc-student`：目录跳转→前置知识依据画像→学习路线跨文件跳转 TEACHER.md→末尾补充内容占位）；
   - 最后初始化 `QUESTION.md`（按 `project-doc-question`，含作答规则说明）。
7. **汇报**：三份文件路径、档位与判据、覆盖/未覆盖清单、未确认项；等待用户确认。

## 后续维护约定

- 学生在 `QUESTION.md` 提问：AI 按作答规则（`/goal` 模式 + `<请回答>` 标记）作答，见 `project-doc-question`。
- 更新 `STUDENT.md` 时同步刷新 §11「补充内容」（依据 QUESTION.md 已答问答的共性/精华）。
- 阅读量大时用 `todo_write` 跟踪五轮进展；`TEACHER.md` §9「证据索引」作为中断续读的事实记忆。

## 注意

- 用户中途提出修改代码/开发新功能：这是开发任务，不在本模式能力内，确认后再切换。
- 目标文档已存在时：先询问（覆盖/追加/跳过），默认不覆盖。
