# project-doc-teacher（TEACHER.md 撰写规范）

定位：**给老师（即 AI）看的项目解析/备课稿**——事实仓库 + 教学设计。学生版学案见 STUDENT.md；学生疑问见 QUESTION.md。所有事实结论标注证据（path::符号）。

## 生成前置

- 承接原 SUMMARY.md 的"事实层"内容：结构全览/数据流向/状态机等不再单独成文件，全部并入本文件（§1~§5、§9）。
- 编写顺序：§0 备课信息 → §1 项目卡片 → §2~§5 事实层（带证据）→ §6~§7 教学设计 → §8 风险 → §9 证据索引；随后据此写 STUDENT.md。

## 结构模板（9 节）

```markdown
# TEACHER.md —— <项目名> 项目解析（老师/AI 备课稿）

> 面向老师（即AI）：本文件是备课笔记与事实仓库；学生版学案见 STUDENT.md，
> 学生疑问见 QUESTION.md。所有事实结论标注证据（path::符号）。

## 0. 备课信息
   生成日期/所依据版本（commit/版本号）/档位与判据（复杂度+行数+理由）/
   阅读范围声明（全量/抽样/圈定子系统；巨型项目在标题注明范围）/验证状态汇总

## 1. 项目卡片
   一句话定位/语言与运行时/入口清单/构建与测试命令（标注已验证）/
   主要自研模块与第三方依赖职责一句话/自解释文档清单（docs、ADR、CHANGELOG）

## 2. 结构全览
   带注释目录树（排除生成物，每目录一句职责）→ 模块-职责表 → 模块依赖方向图（Mermaid）

## 3. 数据流向
   端到端流程（Mermaid flowchart，节点标注 文件::符号）+ 每条流证据链 +
   输入源/输出汇清单 + 错误路径（单列）

## 4. 状态机
   状态表（状态/含义/所在符号）+ 迁移表（源态/事件/动作/目标态/触发点）+
   隐式状态（字段/DB 列/文件/标志位）；确无显式状态机：写明并给出最接近的替代描述

## 5. 关键机制
   构建与打包/配置加载/生命周期与并发/事件与扩展点/错误处理/持久化与网络；
   每机制：怎么用 → 在哪改 → 出错会怎样（带证据）

## 6. 教学设计
   学习者画像（转录）/档位与阅读策略/阅读路径设计（文件顺序+阶段目标）/
   每阶段"学生将学会什么"与检查点设计依据

## 7. 练习设计
   练习集：题干/提示/验证方式/对应源码位置（与 STUDENT.md §7 一一对应，便于批改）

## 8. 风险与未覆盖
   未读或未验证部分/TODO·FIXME·HACK/迁移痕迹与兼容层/历史包袱/推测项（标注"推断"）

## 9. 证据索引
   事实 → 证据（path::符号）对照表；供 STUDENT.md 引用与学生查验，也是续读的事实记忆
```

## 规范

- 每条事实附证据：`path:line` 或 `文件::符号`，行末 `[证据: src/core/scheduler.ts:42]`，或整节开头声明「本节事实均来自 X 文件」。
- 图示：Mermaid 优先（flowchart/stateDiagram），节点含 文件::符号；复杂图拆子图。
- 相对路径；不含绝对路径/机器信息。
- 教学设计（§6~§7）是 STUDENT.md 的蓝图：阅读路径、检查点、练习编号必须与学案一一对应。
- 某节确无内容（如无插件机制）：写明「本项目未采用 X，原因：…」，不硬凑。
- 阅读范围为「部分地图」时（大型/巨型），文档标题与 §0 必须注明范围（如"TEACHER：llama.cpp 之 推理后端"）。
